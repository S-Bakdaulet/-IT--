# Деплой сайта IT-Academy на Railway

Сайт и сервер (Flask) работают как одно приложение: Flask отдаёт и страницы, и API. Поэтому **рабочая ссылка — это адрес Railway** (вход, заявки, админка работают).
GitHub Pages остаётся только как статичная витрина: на нём нет сервера, входить и подавать заявки там нельзя.

## Что уже подготовлено в проекте
| Файл | Зачем |
|---|---|
| `requirements.txt` | Flask и gunicorn (рабочий сервер вместо `app.run`) |
| `Procfile`, `railway.json` | команда запуска `gunicorn app:app --bind 0.0.0.0:$PORT`, проверка `/api/health` |
| `.python-version` | версия Python 3.12 |
| `app.py` | порт берёт из `PORT`, базу кладёт на том Railway (`RAILWAY_VOLUME_MOUNT_PATH`) |
| `.gitignore` | `my_database.db`, `.secret_key` и `.env` **не попадают** в GitHub (там пароли и ключ) |

Gunicorn запускается с одним процессом и четырьмя потоками: SQLite пишет в один файл, а защита от подбора пароля хранится в памяти процесса.

## 1. Загрузите проект на GitHub
```
cd "C:\Users\admin\Desktop\ЛАБ 1"
git init                # если репозитория ещё нет
git add .
git commit -m "IT-Academy: оплата, ИИ-подбор, Railway"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/<репозиторий>.git
git push -u origin main
```
Если репозиторий уже подключён, нужны только `git add .`, `git commit` и `git push`.
Проверьте на GitHub: файла `.secret_key` и `my_database.db` там быть не должно.

## 2. Создайте проект на Railway
1. https://railway.com → войдите через GitHub.
2. **New Project → Deploy from GitHub repo** → выберите репозиторий. Railway сам определит Python и установит зависимости из `requirements.txt`.
3. Откройте сервис → **Settings → Networking → Generate Domain**. Получится адрес вида `https://<имя>.up.railway.app`.

## 3. Подключите том для базы (важно для SQLite)
Файловая система Railway стирается при каждом деплое, и база пропадёт. Чтобы данные сохранялись:
1. На холсте проекта нажмите **+ New → Volume** (или ПКМ по сервису → **Attach volume**) и выберите ваш сервис.
2. Mount path: `/data`.
Приложение само поймёт, что том подключён (переменная `RAILWAY_VOLUME_MOUNT_PATH`), и создаст там `my_database.db`.

## 4. Переменные окружения (сервис → Variables)
| Переменная | Значение | Зачем |
|---|---|---|
| `SECRET_KEY` | длинная случайная строка (например, результат `python -c "import secrets;print(secrets.token_hex(32))"`) | подпись сессий; без неё каждый деплой разлогинивает всех |
| `COOKIE_SECURE` | `1` | cookie только по https |
| `TRUST_PROXY` | `1` | Railway стоит за прокси: нужны настоящий IP и https |
| `ADMIN_EMAIL` | почта администратора | при первом запуске создаётся админ |
| `ADMIN_PASSWORD` | пароль (от 8 символов) | пароль админа |
| `SITE_URL` | адрес сайта на Railway | sitemap и robots |
| `SEED_DEMO` и `DEMO_PASSWORD` | `1` и пароль (от 8 символов) | по желанию: на пустой базе создаст преподавателя `teacher@it-academy.kz` и группы для курсов с записью через сайт, чтобы было что показать. После показа переменные можно удалить |

После изменения переменных Railway перезапускает сервис сам.

## 5. Проверка
1. `https://<адрес>/api/health` → `{"status":"ok"}`.
2. Главная страница: курсы в форме есть, у каждого курса указаны цена и длительность; кнопка «Записаться» у Frontend, Backend и Data Analyst переводит на Stepik.
3. `https://<адрес>/login.html` → вход админа (`ADMIN_EMAIL`) → `/admin`.
4. Создайте группу, подайте заявку студентом, в админке смените «Оплату».

## 6. Автодеплой
Каждый `git push` в ветку `main` запускает новую сборку и публикацию автоматически. Логи: сервис → **Deployments → View logs**.

## 7. GitHub Pages (витрина)
Если нужно оставить и статичную ссылку, она покажет дизайн, каталог и ИИ-подбор. Заявки, вход и админка там не работают, потому что запросы идут на тот же адрес, где нет Flask. В отчёте указывайте ссылку Railway как основную, а GitHub Pages как вторую.

## Если что-то не работает
| Симптом | Причина и решение |
|---|---|
| Сборка прошла, а сайт не открывается | в логах ищите `Application failed to respond`: проверьте, что команда запуска использует `$PORT` (она уже так задана в `railway.json`) |
| После деплоя пропали заявки и пользователи | не подключён том `/data` (шаг 3) |
| Каждый деплой выкидывает из аккаунта | не задана `SECRET_KEY` |
| Вход не держится, https не работает | `COOKIE_SECURE=1` без https (на `*.up.railway.app` https есть); `TRUST_PROXY` не задан |
| `Слишком много попыток входа` | подождите 10 минут или перезапустите сервис (Deployments → Restart): счётчик хранится в памяти |
| Стоимость | на Railway бесплатный пробный период с кредитом и платные тарифы: условия смотрите на https://railway.com/pricing |
